片间互联：从系统需求到 SerDes

为什么芯片之间需要一条“可靠的路”

当计算、存储和 I/O 不再全部位于同一片 die 内，多片 ASIC、chiplet 或 FPGA 就需要跨封装或跨板交换数据。距离和介质可以不同：封装内的 die-to-die、封装基板上的芯片互联、板上的高速连接器和 PCB 走线，都属于片间互联。它可以承载内存读写、加速器的数据流、控制命令，也可以把多个点到点端口组织成环、网格或交换网络。

一次“片间写入”至少涉及四个连续的问题：源端从哪里取数 → 通道能否接收 → 对端是否正确写入 → 源端如何知道事务完成。物理通道只回答其中的一部分。因此设计必须从上到下建立一致的边界：

flowchart LR

关心的问题 主要责任层 出错时不能误判为
写多少、写到哪里、何时完成 事务 / DMA “Link 发出去了”就是写入成功
缓冲不足、错包、丢包、重包 Link “SerDes 有信号”就是数据可靠
训练、块边界、lane 对齐 PCS “CDR lock”就是可接收业务帧
电气信号、时钟恢复、均衡 SerDes / PMA “眼图合格”就是系统事务正确

这张表也是本项目设计和验收的依据：物理层解决跨芯片传比特，Link 解决跨一跳可靠传数据，事务层解决真正的业务完成。

SerDes 在片间互联中做什么

如果将片内的数百根并行数据线直接引出芯片，封装引脚、时钟偏斜、走线长度和信号完整性都会成为约束。SerDes（Serializer/Deserializer）把并行数据转为少量高速差分通道上的串行比特，到对端再恢复为并行数据。它并不是片间互联的全部，而是其物理传输能力的关键来源：

  • 发送端TX：并行用户数据经过所需的编码/gearbox，串行化后由高速驱动器输出；预加重等措施用于适配通道损耗。
  • 跨芯片通道：信号经过 die、封装、连接器和走线；损耗、反射、串扰与通道间偏斜都会影响接收。
  • 接收端RX：均衡器补偿通道损耗，CDR（时钟数据恢复）从输入数据中提取采样时钟，随后反串行化；PCS 再找回块边界和 lane 间的对应关系。
  • 状态管理：PLL lock、TX/RX reset done、CDR lock、block lock、lane alignment 和远端握手逐步成立，才能宣告业务可用。失锁或重训时必须通知上层停止发送、处理未完成事务。

多 lane 并行提高带宽，但接收端不能简单地按线号拼起来：各 lane 的延迟可能不同，需要周期性 marker、deskew 缓冲和对齐判据；其中一条 lane 失锁后，不能继续把错位数据当作正常 payload。

线速率 ≠ 有效业务速率。可将其理解为“物理速率 × 编码效率 × 数据帧载荷比例 × 实际利用率”，再叠加训练、空闲、确认和重传的开销。例如每通道 6 Gb/s、150 MHz REFCLK0、物理侧 8b10b；仅按 8b10b 计算，单条 6 Gb/s 通道的理论编码后数据上界约为 4.8 Gb/s，实际业务还要扣除其他开销。

HNLink 设计：把物理能力变成可信的业务互联

ASIC 目标架构与模块边界

HNLink 是本项目的片间互联方案，不宣称兼容 PCIe、Ethernet、Aurora 等现成协议。面向 ASIC，它让不同节点之间具有可流控、可校验、可恢复的点到点端口；设计的关键不是绑定某个 GTH 或 SerDes 厂商，而是冻结各层对上、对下的契约。

　　HNLink 将一次跨芯片写入拆为事务封装、一跳可靠传输、物理块交付。上层定义“写的是什么、何时算完成”，下层定义“如何让相邻两端正确接收”；层与层通过数据、valid/ready 和错误状态交互，不把物理锁定或单跳 ACK 当成业务完成。

　　DMA / 事务层： 描述符给出源/目的、长度和事务号；发送侧形成请求头及连续数据拍，接收侧按有效字节写入存储。请求头应包含操作类型、会话、事务 ID、长度及必要的路由信息；数据完整性校验覆盖不变的事务信息和有效负载，逐跳可变的路由字段则由每个节点检查。对每笔长度为 L 字节、每拍承载 B 字节的写请求，数据拍数为 ceil(L/B)；最后一拍只提交有效字节。

　　Link 层： 将每个事务数据拍封装为带类型、会话、VC、帧边界、序号及 CRC 的传输单元（FLIT）；另设状态/控制帧承载 ACK/NAK 和信用更新，而不是把它们误认为业务 payload。发送前同时检查窗口和远端所授信用，逻辑条件是 未确认帧数 < 窗口大小 且 该 VC 可用信用 > 0。接收端先校验 CRC 和预期序号，再占用对应 VC 缓冲并按顺序交付；发送端保存未确认数据，丢包/损坏触发重传。累计 ACK 和信用释放不能因重复控制帧而重复计算，重传数据也不能再次提交给事务层。Link ACK 只确认下一跳收到传输单元，不确认事务已写入。

　　PCS 层： 将 Link 的块流变为 SerDes 用户侧可收发的并行数据。若采用自定义 66-bit 块编码，每块由 2-bit 同步头 + 64-bit 内容 组成，用同步头区分控制与数据；通过 TRAIN/START 建链，以 IDLE 维持空闲发送，用带 lane 身份和序号的 AM（alignment marker）支持多 lane deskew。扰码降低长时间低跳变风险，gearbox 在逻辑块宽度与 SerDes 并行宽度之间连续变宽；接收侧依次恢复块边界、锁定和 lane 对齐，再解扰并将有序数据交给 Link。任何背压都必须同步冻结数据和扰码/gearbox/marker 状态，否则恢复后会发生相位错位。如果 ASIC SerDes IP 已提供这些 PCS 功能，就应与 IP 做接口适配，而不是再实现一套冲突的编码。

　　完成与故障边界： 从物理可用、PCS 锁定、Link 建链，到事务写入成功，状态逐级成立。断链、重训或远端复位时停止新事务，未完成事务明确失败；建立新 session 后拒绝旧数据和确认。跨复位不承诺透明的 exactly-once。下节才把这些设计原则映射到 FPGA 的具体位宽、模块和四片回环。

    DMA[DMA / 事务层：存储访问与最终完成]
    DMA <--> MEM[(片内 SRAM / 外部存储)]

例子：一笔 4 KiB 回环事务怎样穿过各层

假设 A 发起一笔正向 4 KiB 写入/回环事务。下表既说明 ASIC 要保留的语义，也交代当前 FULL 原型在做什么：

阶段 正向事务中的动作 要证明的不变量
A / DMA 生成事务头，选定 session、txn、direction、length=4096；4 KiB 按 64 byte 拆成 64 个有效数据拍 同一事务的字节、长度、头部一致
A→B / Link 每拍成为带 VC、序号和 CRC 的可靠帧；远端有接收信用才注入，必要时 replay 不越信用、不静默丢帧、不重复交付
PCS / SerDes 把 Link 块 striping/gearbox 后送往物理边界；B 恢复块锁定和 lane 对齐再解析 锁定前不交业务；暂停/恢复不改变数据顺序
B / DMA 接收全部 4 KiB，检查事务头和 CRC，写入本地槽，向 A 回 WRITE_DONE “一跳接收成功”有存储和校验证据
B→D→C→A 每跳完成同样的存储转发；path 与 hops 随转发更新 确实走过指定节点，而非短路返回
A / 完成 按事务号/方向/长度/path 检查返回值，逐有效字节比较 payload，再走退休握手 Link ACK ≠ WRITE_DONE ≠ 最终 RING_DONE

在 FPGA 上模拟实现 HNLink：四片环路与分层验证

从 ASIC 思路到具体 HAPS 映射

本工程不是将 ASIC SerDes 直接“烧进 FPGA”，而是用 HAPS-80 的物理资源替换 ASIC 的模拟后端，在其上运行可复用的事务、Link 和 PCS 逻辑。选择 A、B、D、C 四个 FPGA 分区组成实际片间环路，既能测试每一跳，也能用 A 的返回数据做端到端对照：

flowchart LR
    A[FPGA A
事务源 / 终点] -->|正向| B[FPGA B
接收 / 存储 / 转发]
    B -->|正向| D[FPGA D
接收 / 存储 / 转发]
    D -->|正向| C[FPGA C
接收 / 存储 / 转发]
    C -->|正向| A

反方向沿同样四条边逆行：A→C→D→B→A。每节点两个相邻端口均有独立链路状态；A 是唯一主机发起业务的节点，B/D/C 不需要各自的 start。FULL 顶层 rtl/full/hnlink_full_ring_top.sv 中四节点 NODE_ID 分别为 A=0、B=1、D=3、C=2，节点编号不是按字母排列。每条边都必须包含两个收发方向：只连正向而悬空反向，会让 Link ACK/维护消息无法工作，甚至让工具裁剪真实接收/发送 CPM 实例。

设计按“先物理、再协议”收敛：

  1. raw 物理基线：先验证 HAPS-80 S104 固定 MGT 资源、板级端点、GTH/CPM/MGTDM 的初始化、6 Gb/s、150 MHz REFCLK0 和调试采样。CDR lock 只能说明物理层工作，不能作为业务 PASS。
  2. 基础逻辑环路：用 haps80_ring_top_sim 直接连接四个节点的逻辑 PMA seam，检查 4 KiB SRAM 数据能否按 A→B→D→C→A 正确转发；它故意绕过真实 CPM/GTH。
  3. FULL 协议环路：用更明确的 DMA、Link、PCS 和 hnlink_cpm_transport 组成生产 FULL top；后者解决 HAPS 的 256-bit CPM 记录并非普通无背压 streaming bus 的问题。
  4. 真实四片实现：四片综合/布局布线、时序和物理检查后打包上板；MGT 初始化、建立新 session，双向事务长期运行并按计数器验收。

FULL 实现：保留协议，适配原型后端

　　DMA：把业务请求封成可验证的事务。 A 从 session/txn/方向/长度 生成确定性 payload，先发一个 512-bit WRITE 头拍（magic/version/opcode/session/txn/length/direction/slot/path/hops/crc），再发 ⌈L/64⌉ 个 512-bit 数据拍，1 ≤ L ≤ 4096 字节。末拍仅前 L mod 64 字节有效（整除时为 64 字节），其余填零。头中的 crc 是端到端事务 CRC：覆盖不可变的事务字段及全部有效 payload 字节；逐跳变化的 path/hops 另行核对，不作为不变数据参与 CRC。hops 表示该方向已走过的跳数，不是链路重传次数。

　　DMA：先存储校验，再转发/退休。 B/D/C 收齐后检查头、会话、方向、预期路径/跳数、拍数、末拍填充和事务 CRC，成功才提交本地 BRAM 槽、回 WRITE_DONE，并从已提交的槽读出 payload，更新 path/hops 重建头发送下一跳。A 在第四跳收到数据后逐字节比较、核对 txn/方向/路径，沿环完成 RETIRE/RETIRE_ACK 后才计入成功。每方向有两个预留槽，但最多一笔有效回环（全网最多两笔）；槽须按写入、下一跳确认及退休状态管理，Link ACK 不能释放槽。这是固定槽与确定性数据的语义验证，尚非任意地址 AXI/DDR DMA 或完整 descriptor ring。

　　Link：把每个 DMA 拍封成一跳可重传的帧。 hnlink_credit_link 不解释 DMA 头：不论头拍还是数据拍，均作为一个 512-bit payload 封装成 11 个 66-bit 块的 DATA 帧：帧头(类型/长度/头 CRC) → 元数据(session/16-bit 序号/VC/first/last) → 8 个数据块 → 帧尾 CRC32。first/last 标明同一 VC 上一组 app 拍的边界，而不是 PCS 的训练信号。VC（虚拟通道）是在同一物理链路上分开的缓冲与信用账本：DATA VC 传 WRITE 头及 payload，RESPONSE VC 传 WRITE_DONE/RETIRE/RETIRE_ACK；另有 5 块的 STATUS 帧传累计 ACK/NAK、两类 VC 的累计释放信用和容量，不占业务 payload。

　　Link：窗口与信用同时限制发送。 DATA/RESPONSE 分别预留 32/8 个接收槽，发送端保留最多 16 个未确认帧；仅当 未确认数 < 16 ∧ 对应 VC 可用信用 > 0 时接受新 app 拍，否则拉低 ready。接收端验证帧头/帧尾 CRC、session、预期序号与缓存容量后按序交付；CRC 错、缺序或超时触发 NAK/Go-Back-N，从未确认帧缓存重发。重复 DATA 不重复提交给 DMA；累计 ACK/累计释放量按差值更新，重复 STATUS 不重复归还窗口或信用。Link ACK 仅证明相邻节点收到帧，不等于 DMA 的 WRITE_DONE。

　　PCS：将 Link 块流变为四 lane 的并行物理数据。 每个块为 2-bit sync + 64-bit body（01 数据、10 控制）。TX 经过 TRAIN → START → ACTIVE，ACTIVE 时依次将 Link 块分配到四个逻辑 lane，无数据插入 IDLE，定期插入带 lane ID、共同序号及 CRC8 的 AM 对齐标记。数据/IDLE 的 64-bit body 扰码而同步头不变；训练、START、AM 是可识别的控制有序集。每 lane 的 66→40 gearbox 连续重组比特，一个 66-bit 块不等于一个 40-bit PMA 拍。

　　PCS：先恢复边界与 lane 顺序，再交还 Link。 RX 经 40→66 gearbox 和 bitslip 搜索同步头、获得各 lane block lock，再依据 AM 的 ID/序号完成 deskew；随后解扰、滤除 IDLE，按发送顺序输出块。训练/对齐未完成时不允许 Link 建链；后端暂停时数据、gearbox 相位、扰码状态及 AM 计数必须一致地暂停，接收缓冲满则以 ready 反压，不能静默丢块。

HAPS 时钟、资源和可观测性。 FULL 顶层使用 20 MHz 低速 fabric profile（早期基础设计采用 50 MHz 业务时钟），100 MHz 用于 A 侧 IICE/debug，150 MHz 是由 MGTDM 管理的物理参考时钟。降低 fabric 注入速度不改变 6 Gb/s 的 GTH 线速。UMR 命令使用跨域握手、一致性状态快照和本地同步释放的复位，避免异步控制直扇出；综合时用双向 CPM 连接及保活字段防止 RX/TX 路径被优化掉；实现时还要核查四片分区、八个收发端点、时钟/USRCLK 约束、CDC 与时序。IICE 触发计数器跳变只证明采样在工作，不代表链路已经 up，更不能取代端到端业务计数。

如何验证：仿真 → 真实链路 → 端到端结论

后续替换 ASIC SerDes 与 DMA]

基础仿真能证明什么？ tb/tb_haps80_ring_dma.sv 在 A 的 SRAM 预填 64 × 512 bit 的固定 pattern（4 KiB），按逻辑 PMA seam 连接四节点，只触发 A；等 ring_done 后逐字比较四片 SRAM。它找得到明显的丢字、乱序、槽写入和转发错误，但不经过真实 HAPS SerDes。基础仿真的约 150 MHz testbench 时钟也不是 FULL 的 HAPS fabric 规格。

FULL 回归能证明什么？ make sim 覆盖 transport 的同值相邻拍、分段刷新、混合字、坏 CRC 和超时；PCS 的 66/40 相位、暂停、训练和重训；Link 的信用耗尽、错误/重复 ACK、序号回绕、重传及重试耗尽；DMA 的 1～4096 字节、尾字节、双向在途、错误头/响应、槽退休和新 session；UMR 的命令跨域与状态快照。FULL 四片独立 scoreboard 核对每笔事务的字节、长度、方向、txn、path 和完成事件，正式回归累计门槛为至少 10000 笔四跳事务；不能用 DMA 单元测试的计数顶替。构建流程绑定源码/配置与仿真凭据，避免修改 RTL 后沿用旧 PASS。

上板能证明什么？ 从 make sim → make bitstream → make bundle 得到经时序/物理验收的同源发布包；服务器的 make run 烧写四片、初始化 MGT、建立新 session、进行正反向传输，要求至少 1000 笔且持续至少 10 分钟。验收同时检查 accepted == completed、forward_good > 0、reverse_good > 0、data_errors == 0、path_errors == 0、timeouts == 0；Link replay/CRC 与 CPM transport CRC 则按相应板测规则分别检查，不把“混合记录被拒绝”混同为业务数据已出错。A 的 FSDB 和状态计数帮助定位是在物理锁定、PCS、Link 还是 DMA；不能仅凭物理寄存器 CDR_LOCK 或 IICE trigger 宣称环路 PASS。

汇报结论：这个项目用真实四片 FPGA 的物理路径，把“DMA 发出事务—Link 可靠传输—PCS 建链—HAPS SerDes 跨片—各节点存储转发—A 检查并退休”连接成了可测试闭环。后续 ASIC 应保留事务号、session、完成/错误、credit/重传、PCS/IP 边界和端到端 scoreboard；替换 FPGA BRAM/UMR、HAPS CPM/MGTDM/GTH 与板卡专用约束，再用 ASIC SerDes 模型、真实时钟复位/CDC、模拟信道和物理实现逐层补足证据。
