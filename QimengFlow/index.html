gen_ram.py分析

不参与仿真运行本身，生成一个 .v 模块，默认输出ram_genvar_style.v,是一个参数化 Verilog RAM 生成器。

  • 核心功能
    生成多读口、多写口、分bank的RAM
    RAM 存储体用 reg [DATA-1:0] bank_x [0:DEPTH-1] 实现
    写入是时序逻辑：always @(posedge clk)。
    普通读是组合逻辑：always @(*)。
    支持同拍写读 bypass：读地址命中本拍写端口时，读数据直接返回写数据，而不是旧 RAM 内容。
    支持 full-table read：把整个 RAM 表展平成一个大向量输出。
  • 地址拆分

  • prf和ram的交互

  • PRF -> RAM 读请求
    PRF 发出 src1_preg/src2_preg 地址，请 RAM 读对应物理寄存器值。

  • RAM -> PRF 读数据返回
    RAM 根据 reg_file_addr_0/1 读出数据，再送回 PRF。
  • PRF -> RAM 写请求
  • ram/prf连接关系

ftq_prf_pc_resp 是响应端口，FTQ 返回：

切分

把 PRF 内部的大块组合逻辑拆成“地址/比较/判定信号输出”和“外部反馈输入”两部分，让 BSD 训练可以把这些中间信号作为可学习/可替换边界。

RAM 交互式切分

读 PRF 从直接数组读改成 RAM 交互式切分

含义是：

  • PRF 不再直接在本组合逻辑里完成 reg_file[src_preg]。
  • PRF 先输出读地址：reg_file_addr_0/1。
  • 外部 RAM/BSD 环境根据地址给回读数据：reg_file_data_0/1。
  • read_operand_with_bypass() 从反馈数据开始，再叠加 bypass。

“读数据转变为和 RAM 交互”。

  • 写 PRF 从直接写数组改成写端口输出

    • 原来 PRF 自己完成写寄存器堆。
    • 现在 PRF 输出写使能、写地址、写数据。
    • 外部 RAM/BSD 负责根据这些写端口更新状态，并在下一轮通过 PI/状态输入再喂回来。

“==”切分

bypass 比较从内部比较改成比较结果切分

所以切分成：

  • C++ simulator 计算 golden 中间信号：logic_out
  • BSD/外部反馈给回：give_in
  • 主数据通路使用反馈值，而不是直接比较值

这让 “寄存器号相等比较” 也成为可训练的切分点。

wakeup切分

Load wakeup 判定被拆成 gate + kill 两级反馈

也就是说 wakeup 逻辑被切成：

  • 是否是有效 load 写回：load_wb_gate_out/in
  • 是否被分支错误杀掉：is_killed_out_0/in_0
  • 最终 wakeup 端口生成仍在 PRF 里顺序扫描

切分控制判断

pipeline 写回寄存器killed指令判断也切出来

所以 comb_pipeline() 里 mispred kill 判断也被拆成一个反馈切分点。

Prf.cpp 的切分策略可以概括为：

  • 大数组访问切出去：reg_file[preg] 变成 addr_out -> data_in。
  • 写数组切出去：reg_file_1[dest] = result 变成 we/addr/data out。
  • 大量相等比较切出去：dest_preg == src_preg 变成 equal_out -> equal_in。
  • 控制判定切出去：load_wb_gate、is_killed 变成 *_out -> *_in。
  • 原 PRF 仍保留数据通路骨架：组装 prf2exe、生成 wakeup、推进 inst_r_1，但关键复杂逻辑通过 BSD feedback 替换。

summary

如果把它抽象成一句话：

正确性不是靠聪明获得的，而是靠不断消灭错误获得的。

或者更严格一点：

任何复杂工作的可靠性 ≈ 多层独立验证机制 × 快速暴露错误机制 × 对自身不可信的认知。

做到这些，无法保证永不出错，但能把“大错漏过所有防线”的概率降到极低。
