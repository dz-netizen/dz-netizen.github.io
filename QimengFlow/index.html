QimengFlow：从 C 模拟器到 BSD/RTL

1. 项目概览

启蒙系列的目标是用 BSD（Binary Structure Diagram）从 C/C++ 模拟器推导硬件逻辑：

  • 启蒙 1 号：自动化设计 CPU 的初步实践。
  • 启蒙 2 号：在前一代基础上加入流水线和多发射。
  • 启蒙 3 号：自动化设计多发射、乱序执行的高性能处理器。

1.1 环境前提

复现流程至少需要 Linux、SSH、tmux、Conda、Python 3、Make、支持 OpenMP 的 g++ 和 Yosys。EDA 节点通常不能直接访问外网，需要先通过服务器提供的代理或跳板建立网络环境。本文中的路径均使用 $BSD、$SIM_SCRIPT 等变量表示，避免依赖个人目录。

文章中的图片使用 Hexo 的 asset_img 标签，资源位于 source/_posts/QimengFlow/；迁移文章时需要同时迁移该目录，并确保站点启用了文章资源目录支持。

1.2 关键术语

术语 含义
BSD 根据输入输出真值关系推导内部电路结构的核心算法
Yosys 开源综合工具链，用于将 Verilog 转换为网表/AIG
AAG ASCII AIG 文本格式
PI/PO BSD 模块的输入/输出 bit 数组
Linux、CoreMark、Dhrystone 用于验证 CPU 功能和性能的程序

1.3 总体流程

整个过程可以概括为：

实践中的验收标准是：

  1. 每个模块的 BSD 输出达到目标准确率，通常要求 acc = 1。
  2. 训练得到的 RTL 与 C 模拟器通过等价性验证。
  3. RTL 接回模拟器后，能够启动 Linux 并通过 CoreMark、Dhrystone 等测试。

模拟器通常按功能拆分后训练。原因是整个 CPU 的 PI/PO 规模过大，直接训练困难；拆分后还可以针对 RAM、旁路、分支控制等逻辑单独调试和优化。

5.1 推荐目录

5.2 修改模块文件

  1. 将 ROB.cpp 改名为 ROB_cpp.h，因为 BSD 构建通常只有一个 .cpp 入口。

7. PRF 模块的核心关系

PRF（Physical Register File）保存物理寄存器值，并处理读、写、写回旁路和执行结果推进。

典型组合逻辑顺序：

  • comb_begin()：将当前状态复制到下一拍副本。
  • comb_awake()：生成唤醒广播。
  • comb_write()：将写回结果写入下一拍寄存器堆。
  • comb_read()：读取源操作数，并处理旁路。
  • comb_pipeline()：推进流水级，处理 flush、kill 和 branch mask。
  • init() / seq()：完成初始化和时序状态更新。

9. 验证链路

9.1 训练、验证和系统测试的区别

训练阶段：

RTL 验证阶段：

系统级验证阶段则把时序 top、RAM 和 RTL 接回模拟器，运行 Linux、CoreMark 或 Dhrystone。

9.2 推荐验证顺序

  1. 单变量 BSD 准确率达到目标。
  2. 对稀有分支做定向采样，并进行模块级 formal/等价性检查。
  3. 将变量连接成组合 top，再做组合电路等价性检查。
  4. 生成 AAG 和 C/C++，确认 bit 区间和函数映射正确。
  5. 将组合/时序 top 接回模拟器，先运行较小的指令数。
  6. 逐步增加 MAX_COMMIT_INST，再运行 Linux 和基准程序。
  7. 最后进行系统级 c-rtl/formal 验证，定位跨周期状态或 RAM 连接问题。

这里的 formal 有两种用途：训练后用于检查局部模块/组合逻辑是否等价；接入时序 top 后用于检查带状态和 RAM 的系统级行为。两者不能互相替代。

9.3 c-rtl 验证骨架

如果验证对象已经接入 RAM，应将 RTL 端输出替换为时序 top 的对应输出，而不是继续比较纯组合 top。

10.4 输出未初始化

第一次训练或验证打开：

确认所有输出在计算前已初始化后再关闭。尤其注意新模拟器中部分 class 不能简单用 {} 初始化，需要逐项初始化到确定值。

10.5 训练超时

处理顺序：

  1. 先单进程运行对应变量，确认不是编译或接口错误。
  2. 检查是否存在过大的比较逻辑、全表读或未拆分的多端口连接。
  3. 调整训练样本量和并行度；必要时使用按变量拆分。
  4. 备份 rtl_set/，避免长时间训练完成后误删结果。

10.6 验证失败的定位顺序

不要直接从整个 CPU 的日志开始排查。先缩小到单个变量、单个输出 bit 和最小反例，再回到组合 top 或时序 top。

12. 复现清单

  • 确认 config.h、IO.h、类型定义和模块实现版本一致。
  • 生成接口后检查 PI/PO 宽度、结构体指针、数组展开顺序。
  • 先用简单模块验证 BSD 环境，再训练复杂模块。
  • 首次运行打开 OUT_INITIAL_DETECT。
  • 随机训练达到目标后，补充稀有分支的定向样本。
  • 训练、组合 top、时序 top 分阶段验证。
  • 并行进程使用独立的构建目录和日志目录。
  • 出现错误时先单进程、单模块调试。
  • 大输出按变量或 bit 区间拆分，保持两侧映射一致。
  • 备份训练得到的 RTL，再开始后续转换和综合。
